ZenBook Platform

System Settings module for zenbook-scripts on ASUS ZenBook Duo and related models. Configures keyboard backlight, dual-eDP dock, ScreenPad, sleep/resume policy, scheduled profiles, and the touchpad live filter.

Overview tab

Shows output of platform-probe: DMI product, fan backend, platform profile, attached touchpads, and USB/BT keyboard nodes. This text is loaded automatically when the module opens — you do not need to press Refresh first.

Use Refresh after attaching the keyboard dock, resuming from sleep, or switching Bluetooth/USB transport.

Displays tab

Status for Duo dock and ScreenPad is populated when the module opens. Refresh only if you changed hardware state while System Settings stayed open.

Duo dock (UX8406 / UX581 / UX582)

The lower eDP panel is managed by platform-duo-dock, not by ordinary kscreen-doctor alone. Screen swap toggles stacked layout via platform-screen-swap.

  • Docked — enable lower panel in stacked layout
  • Undocked — disable lower panel
  • Screen swap — swap which panel is primary upper/lower

ScreenPad (UX5400 and similar)

Secondary panel backlight via screenpad (asus_screenpad sysfs). This is not the same as Duo eDP-2 dock management.

  • On / Off — power and brightness
  • Sync to main — match main panel brightness percentage once

Sleep / Resume tab

Per-user session policy stored in ~/.config/zenbook-scripts/session.json and applied by platform-session.

Restore presentation after plasmashell replace
Re-applies PowerDevil presentation mode after plasmashell --replace. Presentation inhibit is owned by plasmashell and is lost on replace; PowerDevil itself survives.
Watch QSG render threads
After resume, count plasmashell threads named QSGRenderThread / Mesa (gdrv, traceq). Useful on Plasma 6.6 Wayland when resume leaks render threads (common on dual-eDP Duo). Off by default.
Auto plasmashell --replace
When watch is enabled and thread count exceeds the threshold, run plasmashell --replace. Does not kill applications — kwin_wayland keeps windows.
QSG thread threshold
Total QSG/Mesa-related threads across plasmashell PIDs before auto-replace. Healthy: under ~16; leaked resume on Duo often exceeds 32. Default 32, range 1–256. Manual check: platform-session plasmashell check.

Profiles tab

Edits ~/.config/zenbook-scripts/profiles.json: day/night schedules, fan curves, keyboard backlight levels. Apply writes JSON; platform-profiles evaluates schedules via cron.

Touchpad tab

Soft accel and palm filters only work when the live filter is running. Use Start live filter or OpenRC zenbook-platform-touchpad. After changing knobs, click Apply — the module restarts the live filter if it was already running. Raw libinput in Plasma is unchanged; only the uinput virtual device gets filtered motion.

Config path (user overrides system):

~/.config/zenbook-scripts/touchpad.json   (preferred)
/etc/zenbook-scripts/touchpad.json       (fallback)

Controls

Profile enabled
Whether this touchpad participates in the live filter daemon.
Filter profile: Default
Static chain: typing_inhibit → exec_delay → outlier_reject → soft_accel. Outlier reject drops single-frame teleports above Max delta.
Filter profile: Adaptive
Replaces fixed outlier thresholds with adaptive_matrix, which learns per-axis noise online. Small isolated glitches are attenuated (clamped), not dropped — fast swipes and ongoing gestures pass through unchanged. State persists under ~/.config/zenbook-scripts/adaptive-touchpad/.
Typing inhibit
Suppresses pointer motion briefly after keyboard activity (palm-while-typing).
Exec delay
Buffers motion briefly so typing inhibit can arm before a stray pad event fires.
Outlier reject / Max delta
Only used in Default profile. Ignored when Adaptive is selected.
Soft accel / Soft gain
Scales ABS motion on the uinput path (DE AccelSpeed bypass). Try 160–200% (gain 1.6–2.0). Nonlinear mode and calibration are in the full tuner GUI.
Start / Stop live filter
Runs platform-touchpad run --replace or stop.
Live status
Output of platform-touchpad status — loaded when the module opens. Shows config path, daemon PID, per-pad filter chain and counters.

USB vs Bluetooth: Duo keyboard touchpad settings are stored per transport under a logical device entry. KCM saves to the nested transports.usb or transports.bluetooth block. Stale flat keys (name|phys) are removed on save.

Open full tuner… launches platform-touchpad-gui (calibrate wizard, live monitor, adaptive stats).

Configuration files

  • ~/.config/zenbook-scripts/session.json — sleep/resume, plasmashell watch
  • ~/.config/zenbook-scripts/profiles.json — schedules, fans, keyboard
  • ~/.config/zenbook-scripts/touchpad.json — live filter knobs
  • ~/.config/zenbook-scripts/adaptive-touchpad/*.json — learned adaptive state
  • /etc/zenbook-scripts/ — system-wide defaults (overridden by user config)

OpenRC services (Gentoo)

  • zenbook-kb-hotkeys — Fn-row, keyboard backlight hotkeys
  • zenbook-kb-lid — lid-close keyboard backlight policy
  • zenbook-platform-touchpad — live filter daemon
  • zenbook-screenpad — ScreenPad boot brightness (UX5400)

Install and enable via configure.py --all-yes --defaults from the zenbook-scripts tree.

Troubleshooting

Live status empty in KCM

Rebuild and install the KCM plugin, then restart System Settings. Status is fetched synchronously on module load. If empty, run platform-touchpad status in a terminal — the KCM shows the same output.

Soft accel does nothing

  1. Start the live filter (KCM button or platform-touchpad run --replace).
  2. Enable Soft accel and Apply.
  3. Confirm status shows soft_accel: in=… out=… counters increasing while moving.
  4. Ensure you are using the filtered uinput device — not testing on a second unfiltered pad.

Adaptive feels sticky or jumpy

Older builds dropped glitch frames entirely (cursor freeze). Current adaptive attenuates small spikes instead. Reset learned state: rm ~/.config/zenbook-scripts/adaptive-touchpad/*.json, restart live filter. If problems persist, switch to Default profile temporarily and report via GitHub issues.

Help button shows “Documentation not Found”

Handbook must be installed under /usr/share/doc/HTML/en/kcm_zenbook_platform/index.html. Rebuild KCM: cd plasma/kcm && sudo env PREFIX=/usr ./build.sh --system.

Displays tab shows “(no status yet)”

Module should auto-load on open. If hardware was just attached, click Refresh once. Check platform-duo-dock status or screenpad status manually.
